# seventh_task_rag

Учебный RAG-пайплайн. День 1 загружает локальные текстовые документы и готовит их к нарезке на чанки.

## База знаний

Положите свои документы в `knowledge_base/`:

- формат: `.txt` или `.md`
- кодировка: UTF-8
- один файл — один документ
- минимум 5 файлов

PDF, DOCX и HTML загрузчик не читает. Если текст в другом формате, сохраните его как `.txt`.

## Запуск

```bash
python3 main.py
```

Программа печатает число загруженных документов, длину каждого после очистки и число чанков. Очистка убирает лишние пробелы и пустые строки.

Если в папке нет подходящих файлов, программа сообщает об этом и завершается с кодом 1.

## День 1

- есть папка `knowledge_base/`
- программа читает `.txt` и `.md`
- текст загружается и очищается
- в консоли виден список документов и их длина

## День 2

Документы режутся на чанки по 500 символов с перекрытием 80. Граница сдвигается к переводу строки или пробелу, чтобы не разрезать слово. У каждого чанка есть `document_id`, `source_name` и `chunk_id`.

`python3 main.py` печатает число чанков по каждому файлу и три примера из самого длинного документа.

## День 3

Weaviate запускается локально и хранит чанки с векторами OpenAI `text-embedding-3-small`.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
docker compose up -d
python3 main.py index
```

В `.env` нужна переменная `OPENAI_API_KEY`. Файл не коммитится.

Команда удаляет коллекцию `KnowledgeChunk`, создаёт её заново и загружает текущие чанки. Повторный запуск не оставляет дубликаты: число объектов равно числу чанков. В консоли печатаются это число и один объект с `chunk_id`, `document_id`, `source_name` и началом текста.

## День 4

Поиск берёт embedding вопроса той же моделью и возвращает 3 ближайших чанка из Weaviate.

```bash
python3 main.py ask "Как подключить автоплатёж?"
python3 main.py demo
```

`ask` печатает semantic search: distance, `source_name`, `chunk_id` и короткий текст. Меньшая distance означает более близкий чанк.

`demo` прогоняет пять вопросов и для каждого показывает semantic search и hybrid search. У hybrid выше score — релевантнее фрагмент.

## День 5

Ответ модели строится только по трём чанкам, найденным semantic search. Модель `gpt-4.1-mini` не должна добавлять факты вне этого контекста. В ответе есть флаг достаточности контекста и источники: `chunk_id` и `source_name`.

```bash
python3 main.py answer "Как подключить автоплатёж?"
python3 main.py compare
```

`compare` задаёт пять вопросов дважды: без фрагментов базы и с retrieved context. Рядом видно, что ответ с поиском опирается на конкретные правила из документов.

## День 6

Ответ даётся только если ближайший чанк ближе порога distance 0.55. Иначе модель не вызывается, источников нет, а ответ такой: в базе нет достаточно близкого контекста.

```bash
python3 main.py evaluate
```

Команда проверяет пять вопросов по базе и пять посторонних. Для каждого печатаются distance, `source_name` и решение: ответ или отказ.

Рабочие настройки этой базы: чанк 500 символов и overlap 80, semantic top-3. Документы режутся на 2–6 фрагментов, граница не попадает в слово. Distance сравнивается с порогом, поэтому ответ идёт через semantic search. Hybrid остаётся в `demo`: на вопросе про шум в Москве он поднимает нужный фрагмент выше, но файл тот же.

У тематического вопроса в top-3 иногда есть соседний документ, например автоплатёж рядом с регистрацией. Порог смотрит только на лучший чанк. Наблюдаемые distance удачных вопросов 0.14–0.36, посторонних 0.73–0.89, поэтому порог 0.55 их разделяет.
